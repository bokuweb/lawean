# 10. 時間の整合性 — 施行日・期間・経過措置の矛盾は誰が担保するか

状態: 設計（2026-09-20）。担保の鎖のうち §3 の 2 と 3 は実装済み、4 は未実装。Lean は関与しない（理由は §3 の 5）。

## 1. 問い

「施行日と法令内の期間の定義が矛盾している」ような異常は、patch 代数（[08](08-amendment.md)、[ADR-0013](adr/0013-identity-patches.md)）では出てこない。
patch 代数は条文の**構造**しか見ないからである。例:

| 例 | 何が矛盾するか |
|---|---|
| 令和3年改正の施行日を 2023-01-01 に遅らせた改正案に対し、施行令（2022-05-18 施行）が「第三十八条第四項」を指す | `[2022-05-18, 2023-01-01)` の区間だけ、施行令は旧第4項（通知義務）を指す。参照は形式的に解決するが意図と違う |
| 附則の経過措置「施行前に設定した借地権には旧法を適用」と本則「存続期間は 30 年」 | 契約日が施行日の前後どちらかで適用される Rule 集合が変わる。どちらの期間が効くかは Fact（契約日）に依存する |
| 法令 B が A の「一年以内の期間を定めたものに限る」を前提に値を計算している | A の改正で期間が変わると B の前提が崩れる。参照先は同じ stable_id のまま |

これらは「時間」を持つ意味層の問題で、担保するのは **Semantic IR の Temporal + Z3**（[07](07-verification.md)）と、**施行日の比較**（[09](09-cross-law-impact.md)）である。

## 2. モデルにある「時間」

[04](04-semantic-ir.md) §Temporal の型をそのまま使う。

| 概念 | 型 | 値の出どころ |
|---|---|---|
| 施行日 | `Event::Symbol("施行日")`、`RuleTemporal.effective` | 法令内では確定しない（政令委任）。リビジョンの `enforced_on` から束縛する。未確定なら改正シナリオ（[08](08-amendment.md) §3）の分岐 |
| 期間 | `Period { from: Event, length: Duration, direction }`、`Window`、`PeriodValue::Indefinite` | 原文。計算規則は民法第140〜143条（[minpo-140-143](03-examples/minpo-140-143.md)）。Backward（遡り）は `Unknown(Ambiguous)` |
| 経過措置 | `RuleTemporal.facts_before_boundary` | 附則。「施行前の事実にも適用」（附則第4条）/「施行前の事実にだけ適用」（附則第6条） |
| 時期の区間 | `[t_A, t_B)` | 改正の施行日 `t_A` と参照元の施行日 `t_B` の比較（[09](09-cross-law-impact.md) §3） |

patch 代数の `Revision` / `AmendUnit` は時間を持たない。施行日は改正単位の属性（`Enforcement`）で、シナリオの列挙と時期の区間の計算にだけ使う。

## 3. 担保の鎖

矛盾は 1 つの層では捕まらない。原文から結論までを鎖にすると次の 5 段になり、**弱い環は 1**である。

| # | 担保するもの | 手段 | 誰が | 状態 |
|---|---|---|---|---|
| 1 | Semantic IR の `Temporal` が原文に忠実であること。施行日・期間・経過措置が正しい型で書かれていること | 層 1 の規則（期間の正規表現）+ 人のレビュー。Provenance と確度を付け、逆変換で原文と並べる（[ADR-0012](adr/0012-structured-authoring.md)） | 人 | 型と手書き 15 例。経過措置は附則第4・6条の例のみ |
| 2 | 時期の区間。参照元が改正前の状態を意図しているのに、区間内で旧内容を指すこと | 施行日の比較（決定的）。`lawean-space::impact` の `TimingGap`。改正前後の本文を両方示して人に判断させる | Rust | **実装済み**（[09](09-cross-law-impact.md) §5 テスト計画 2） |
| 3 | 期間・数量の性質。「存続期間 ≥ 30 年」「更新後の期間 ≥ 20 年」が全ての Fact について成り立つか | Semantic IR → SMT-LIB、期間は月数の Int に正規化、Z3 で証明または反例 | Z3（`lawean-verify`） | **実装済み**（6 性質。手書き IR のバグ 1 件を反例で検出） |
| 4 | 経過措置による適用 Rule 集合の切替。Fact の発生時点（契約日など）が施行日の前か後かで、旧法と新法のどちらが効くか | Temporal resolver が `facts_before_boundary` で場合分けし、各場合を 3 の検査に渡す。「施行前の事実に旧法と新法の両方が適用される」「どちらも適用されない」を矛盾として出す | Rust + Z3 | **未実装**。型はあるが検査に繋がっていない |
| 5 | 3・4 で Z3 が見つけた反例を確定した証明にすること | Z3 の反例の Fact を証人にして Lean で `decide`（[09](09-cross-law-impact.md) §4） | Lean | **設計のみ**。Semantic IR の Lean 化は後回し（[ADR-0011](adr/0011-lean-as-reference-for-consolidation.md) §5）。Z3 の反例で用は足りる |

Z3 も Lean も **1 を検査しない**。IR が原文と違えば、その IR について正しい結論が出るだけである。だから 1 は人が担い、逆変換（`lawean-render`）が人の道具になる。

## 4. 検出できる矛盾の形

| 矛盾 | 定式化 | 手段 | 状態 |
|---|---|---|---|
| 時期の区間 | `t_B < t_A` かつ B の参照先が改正で変わる → `[t_B, t_A)` で旧内容を指す | 施行日の比較 | 実装 |
| 期間の不整合（自法令内） | `∃ facts. applies_R(facts) ∧ ¬ (attr op v)` | Z3 sat → 反例 | 実装 |
| 期間の不整合（他法令） | B の条件が A の期間の値を参照し、A の改正後に `∃ facts. applies_B ∧ ¬ cond_B'` | Z3（法令空間で A・B を 1 モデルに） | [09](09-cross-law-impact.md) §3 に定式化、テストは意味変化まで |
| 経過措置の衝突 | `∀ fact. |{ R : applies_R(fact) ∧ R が fact の時点で有効 }| = 1` の否定 | Temporal resolver で場合分け → Z3 | 未実装 |
| 未確定施行日 | 施行シナリオごとに上を繰り返す | `scenario::explore` × 上の検査 | シナリオ列挙は実装、時間検査との結合は未 |

## 5. 担保しないもの

- **IR の忠実さ**（§3 の 1）。人のレビューが唯一の手段
- **施行日そのものの誤り**。改正法の附則を読み間違えて `enforced_on` が違えば、全部その日付で計算される。入力データの問題で、検査の前提
- **遡りの期間計算**（「一年前から」）。民法に規則が無く `Unknown(Ambiguous)`。[TODO](TODO.md)
- **休日の繰り延べ**（民法第142条）。未実装
- **附則の略称**（「新法」「旧法」「同法」）の解決。未実装なので、経過措置の参照が解決できない場合がある
- **官報正誤・調整規定の見落とし**。改め文の外にある

## 6. サービスでの置き場所（[ADR-0015](adr/0015-service-architecture.md)）

| 検査 | 動く場所 | 理由 |
|---|---|---|
| 自法令内の期間の性質（§3 の 3） | ブラウザ（Z3 の WASM ビルド） | 入力は 1 法令の Semantic IR で小さい。計測は未 |
| 時期の区間、他法令の期間（§3 の 2、§4 の 3 行目） | サーバー | 法令空間（他法令のリビジョン）が要る |
| 経過措置の場合分け（§3 の 4） | ブラウザ | Temporal resolver は決定的な計算 |
| Lean | 関与しない | 時間の検査は反例探索であって、全入力についての定理ではない |

担当者に返すのは「この Fact のとき矛盾する」という反例であり、「証明した」ではない。文言もそう書く。
