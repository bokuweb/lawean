# 0012. 既存法令は一回だけ構造化し、改正は構造化記述で書いて改め文と条文を生成する

状態（ハネの生成は実装済み 2026-09-21: Rust `hane::render_fix` が手当てを生成し `lawean-check` が改め文の形で出す。Lean `Refs.lean` で完全性を証明）: accepted（2026-09-20）

## 文脈

「自然言語 → Z3 / Lean」の信頼境界は自然言語 → Semantic IR の段にあり、Z3 も Lean も IR が正しいかは検査しない
（[docs/09](../09-cross-law-impact.md) の議論、2026-09-20）。[ADR-0009](0009-layer2-decisions-via-grande.md) は生成 LLM を
IR の生成経路から外したが、その理由は「改正のたびに再抽出すると同じ入力から同じ IR が出ない」ことだった。

## 判断

1. **既存法令の構造化は一回きりのブートストラップ。** 手段は問わない（層 1 の規則 + 人手 + frontier model）。
   出力には `Author::Llm(model)` / `Author::Human` と確度を必ず付け、人がレビューしてから `High` にする。再現性は問わない（二度やらない）
2. **改正は構造化記述で書く。** 改正案は Semantic IR / Source IR への patch として書き、そこから改め文（`Op` → 改め文）と溶け込み後の条文を**生成**する。
   自然言語の改め文を書いて IR に再抽出する経路は、移行期の併用に限る
3. **逆変換を一級の機能にする。** `Op` → 改め文、Semantic IR → 日本語。人が読める中間物が無いと IR はレビューできない。
   改め文の逆変換は往復（parse ∘ render = id）をテストで保証する
4. 到達点は「構造化記述が正、官報の自然言語は生成物」。法制度上は自然言語が公布の正本であり続けるので、
   当面は新旧対照表と同じ**審査資料としての正本**と位置づける（デジタル庁のエディタ検証と同じ向き）
5. ADR-0009 の「生成 LLM を中核から外す」は、**改正の経路**について維持する。ブートストラップには使ってよい

## 理由

- 再現性が要るのは改正の差分であり、改正が構造化記述なら差分は定義により決定的
- 全法令の自動 IR 化は要らない。改正案の審査で意味的矛盾を見るのに要る Rule は数本で、手書きで足りる
- 逆変換は安く、法律家がレビューできる唯一の形

## 結果

- `lawean-render`: `Op` → 改め文（往復テスト）、Semantic IR → 日本語
- `lawean-llm` の位置づけを「ブートストラップ用」に戻す（ADR-0009 の「残余・レビュー補助」から拡大）
- 構造化記述の入力形式（人が書く IR のテキスト表現）は未決。`lawean-semantic::build` の Rust 構築子か、専用の記法か
