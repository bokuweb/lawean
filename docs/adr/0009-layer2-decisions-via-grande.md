# 0009. 層 2 の判定は grande（System One、Gemma 4 E4B）で行い、生成 LLM は中核から外す

状態: accepted（2026-09-20）。実装は**後回し**（[TODO](../TODO.md)）

## 文脈

[ADR-0008](0008-extraction-strategy.md) は層 2（条件節の中身・効果の引数）を「LLM に IR スキーマで出力させ、層 1 と突き合わせる」とし、
`lawean-llm`（Claude、structured outputs）まで実装した。しかし問い直すと:

- 層 2 で必要なのは**生成ではなく判定**。述語と引数の候補は格助詞（が／を／に／から／まで）と節末動詞から規則で出せる。
  残るのは閉じた選択肢からの判定 — 「できる」が Permission か Power か、2 つの述語が同じ事実か、主体はどの定義語か、評価概念か、括弧書きが場合分けか
- 生成 LLM を IR の生成経路に入れると、同じ入力から同じ IR が出ない（改正 diff に抽出のゆらぎが混ざる）、監査できない、モデル更新で全法令を再抽出
- 確度を「medium 固定」にする逃げをしていた

[bokuweb/grande](https://github.com/bokuweb/grande) は state + 型付き質問 → 較正済み確率を 1 forward pass で返すランタイム（生成なし、ローカル、日本語、Gemma 4）。

## 判断

- 層 2 は **規則（格助詞パーサ）で候補を出し、grande の typed questions で判定する**。モデルは **Gemma 4 E4B**
- 判定の確率をそのまま `Provenance.confidence` にする（温度スケーリング済み）。`Author::Model("grande/e4b")` 相当を追加
- 生成 LLM（`lawean-llm`）は中核から外す。残すのは「規則でも grande でも取れなかった残余」への補助と、人のレビュー補助。IR の生成経路には入れない

想定する質問:

| 判定 | 型 | 質問（案） |
|---|---|---|
| Permission / Power | `choice` | この「できる」は、相手方の法律関係を変える権限（請求権・解除権・形成権）か、単に許容される行為か |
| 述語の同一性 | `noul` | [A] と [B] は同じ事実を指すか |
| 引数の役割 | `choice`（有効な定義語 + その他）/ pointer | 「請求した」の主体は誰か |
| 評価概念 | `noul` | この語は判断者の裁量に委ねられているか |
| 括弧書き | `choice` | この括弧書きは本文の値を場合分けで置き換えているか、説明か |

state は層 1 の骨組み（文・条件節・参照・定義語）を `path: value` 行で描く（`ParagraphInput::user_message()` とほぼ同じ）。

## 理由

- 決定性・監査可能性・ローカル実行・無料。法令コンパイラの性質に合う
- 確度が数値で出る。IR の設計（ADR-0001 / 0005）が求めていたもの
- 判定の種類が閉じているので、pointer head を学習すれば精度を上げられる。ラベルは借地借家法の「できる」44 文 + 民法の数百文で現実的

## 結果・リスク

- ゼロショット精度は未知（JNLI 61%）。Permission / Power は法学概念なので head の学習が前提。最初の実験は「できる」44 文を人がラベルして精度を測る
- 述語同一性は文ペアで n²。同じ条・参照関係にあるペアに絞る
- `lawean-llm` は削除せず、用途を「残余・レビュー補助」に限定する旨を README に書く
